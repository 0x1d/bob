# Retrospective Index

Canonical index for retrospectives.

## Purpose

Retrospectives capture outcomes and process improvements after implementation or
specification work.

## Retrospective Format

Each retrospective should include:

- **ID** - unique identifier (e.g., `RETRO001`)
- **Title** - concise retrospective title
- **Spec References** - reviewed/affected specs
- **Achievements** - what went well
- **Impediments** - what slowed delivery
- **Learnings** - reusable improvements
- **Date** - when the retro was authored
- **Guidelines** - follow-up recommendations

## File Naming

Use `RETROXXX.md` with zero-padded numeric IDs.

## Authoring Rules

1. Create a retro after meaningful milestones or batches of completed work.
2. Keep focus on process and systemic improvements.
3. Number sequentially and update this index in the same change.
4. Link retrospectives to plans and resulting spec updates.
5. Keep action items concrete and testable where possible.
